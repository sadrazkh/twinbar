## 🧑‍💻 VS Code twins, and a straight answer about Antigravity

**A second VS Code with its own GitHub and Microsoft sign-in, settings and
history, sharing your extensions.**

### ✨ New

- 🧑‍💻 **VS Code is back.** Since 1.10x, VS Code keeps `Code.exe` in its
  install folder and Electron's files in a version folder next to it, so
  Twinbar thought it wasn't an Electron app. It finds it there now, and
  `twinbar apps` and **New profile...** list it again.
- 🧩 **Extensions stay shared.** VS Code keeps extensions in
  `%USERPROFILE%\.vscode\extensions` whatever the data folder, so a twin uses
  the ones you already have. Making the profile says so, and how to give it
  its own: `-AppArgs '--extensions-dir "<a folder>"'`. The same goes for
  editors built on VS Code (Cursor, Antigravity IDE...).

```powershell
twinbar new -App "Visual Studio Code" -Name Work -Color blue
twinbar open "Visual Studio Code Work"
```

### 🔁 Changed

- 🚫 **Antigravity can't be twinned, and now says so.** It keeps your Google
  sign-in in Windows Credential Manager and its agent's data in
  `%USERPROFILE%\.gemini\antigravity`, outside the data folder Twinbar gives
  it, so every copy was signed in to the same account. Rather than make a
  twin that only looks separate, Twinbar explains why it can't.
- 🧪 **Antigravity IDE** can still be twinned; Twinbar mentions that its
  agent's data (`%USERPROFILE%\.gemini\antigravity-ide`) is shared with the
  main copy.

### ℹ️ Good to know

- Made an Antigravity profile already? Remove it: `twinbar remove
  "Antigravity 2" -DeleteData` (use the name `twinbar list` shows).
