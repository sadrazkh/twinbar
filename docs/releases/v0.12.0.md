## 🧑‍💻 VS Code twins with their own Claude Code and Codex

**A second VS Code now signs in to Claude Code and Codex on its own, not
just to GitHub and Microsoft.**

### 🐛 Fixed

- 🔑 **Claude Code and Codex were the same account in every VS Code.** They
  keep their sign-in in `%USERPROFILE%\.claude` and `%USERPROFILE%\.codex`,
  outside the data folder Twinbar gives VS Code. A VS Code profile now gives
  them folders of their own inside its data folder (`CLAUDE_CONFIG_DIR` and
  `CODEX_HOME`), so each twin signs in to them on its own, in the editor and
  in its terminal. Their settings start empty there.
- 🗂️ **VS Code's shared storage stays apart.** VS Code 1.14x keeps recent
  folders, workspace trust and some secrets in `%USERPROFILE%\.vscode-shared`,
  which every copy used to share, and a twin couldn't read the secrets. A
  twin now has its own (`--shared-data-dir`).
- 🧹 **Removing a VS Code profile cleans up fully.** VS Code's Git extension
  makes a small folder (`askpass`) that even you aren't allowed to open, so
  it couldn't be deleted. Twinbar now gives you back access to it before
  removing the data.

Your extensions are still shared, as before. The same goes for editors built
on VS Code (Cursor, Windsurf...).

```powershell
twinbar new -App "Visual Studio Code" -Name Work -Color blue
```

### 🔁 Changed

- 🚫 **Antigravity IDE can't be twinned either, and says why.** Its editor
  signs in on its own, but its agent uses the same Google sign-in (Windows
  Credential Manager, `gemini:antigravity`) and folder
  (`%USERPROFILE%\.gemini\antigravity`) as Antigravity itself, so a twin's
  agent was signed in to the same account.

### ℹ️ Good to know

- Made a VS Code profile with 0.11.0? Run `twinbar rebuild -All` once (or make
  it again) to give it these folders.
- Made an Antigravity IDE profile? Remove it: `twinbar remove "Antigravity
  IDE 2" -DeleteData` (use the name `twinbar list` shows).
