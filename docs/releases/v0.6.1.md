## 🔧 Better proxy advice, after Claude got lost behind SOCKS

**If a signed-in Claude profile kept asking you to choose a folder, this is
why, and here's the fix.** Claude Code's sessions inside Claude skip a SOCKS
proxy ("not supported by downstream HTTP agents") and try to connect
directly, so behind a SOCKS proxy its sessions and folders don't load. Through
an HTTP proxy they work.

### 🐛 Fixed

- With a SOCKS proxy, the launcher no longer puts the SOCKS address in
  `HTTPS_PROXY` and `HTTP_PROXY`, where most Node.js code can't use it and
  fails. It goes in `ALL_PROXY` only. HTTP proxies still set all three.

### 💡 Changed

- Setting a SOCKS proxy (`new`, `change`, `doctor`, and the window's hint) now
  says which apps can't use it outside Chromium, and to use the proxy's HTTP
  address if it has one.

### 👉 What to do

Use your proxy's **HTTP** port for apps like Claude. xray's and v2ray's local
ports usually speak HTTP as well as SOCKS:

```powershell
twinbar change "Claude Work" -Proxy http://127.0.0.1:10809
```

Your sessions were never lost: they're still in the profile's data folder and
come back as soon as Claude can reach its servers.
