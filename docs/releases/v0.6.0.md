## 🛡️ A proxy for each profile, with a kill switch

**Send one profile through your VPN's proxy and keep the other direct.** Give
a profile a proxy and its traffic goes only through it. If the proxy goes
down, the profile goes offline instead of quietly going around it. And you can
check, any time, which IP address the world sees for it.

### ✨ New

- 🌐 **`-Proxy`** for `new` and `change`, and a **Proxy** field in the window:
  `socks5://`, `http://` or `https://` with a host and port. `-Proxy none`
  removes it.
- 🔒 **A kill switch built in.** The proxy is strict: Chromium never falls back
  to a direct connection, names are looked up through the proxy (only the
  proxy and localhost are looked up locally), and WebRTC can't send UDP around
  it. Microsoft Store apps go without the name rule, because Claude doesn't
  start with it; their connections still only go through the proxy.
- 🔎 **`twinbar ip` and Check IP**: the IP address, place and network the
  world sees for a profile, through its proxy, next to the one without a
  proxy. If they're the same, it tells you.
- 🩺 **`doctor` checks the proxy answers.**

```powershell
twinbar new -App Postman -Name Work -Proxy http://127.0.0.1:10809
twinbar ip "Postman Work"
```

### 🧪 Measured, not guessed

Every app was watched for 30 seconds through a logging proxy, with every TCP
connection it opened:

| App | Through the proxy | Proxy down |
|---|---|---|
| Postman 12.33 | everything | nothing gets out ✅ |
| Claude 6.28 (Store) | everything | nothing gets out ✅ |
| Bruno 4.3 | its web traffic | one Node.js connection still gets out ⚠️ |

What an app does in its own Node.js code can go around Chromium's proxy; for
that, your VPN client's own kill switch is the tool.
