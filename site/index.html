Two of every app.

Twinbar gives Slack, Claude, Postman, Discord and other Electron apps a second copy on Windows that signs in separately, with its own taskbar button, its own icon and its own data. The original app isn't touched.

Features

Everything for more than one account

From a second sign-in to a proxy with a kill switch, backups and updates that install themselves.

Under the hood

Simple, and the app stays untouched

No patching, no injecting, no re-signing. Just the right switches and a window property.

1

A Start menu entry

“Slack Work” starts Twinbar's tiny launcher with the profile's id.

Slack Work.lnk → twinbar-launcher.exe slack.work
2

The same app, its own folder

The launcher starts the installed app with its data folder pointed at the profile's own, plus its proxy and appearance.

slack.exe --user-data-dir="...\Twinbar\data\slack\work" --proxy-server=http://127.0.0.1:10809
3

A taskbar button of its own

It puts the profile's AppUserModelID and icon on the app's windows, so Windows gives it a button of its own.

AppUserModelID = Twinbar.slack.work

Measured with UI Automation on real apps: an ID set on the window wins over anything given at start-up.

Privacy

A proxy for each profile, with a kill switch

Send your work profile through your VPN's local proxy and keep the other one direct.

  • Strict. Chromium never falls back to a direct connection.
  • No DNS leaks. Names are looked up through the proxy.
  • No WebRTC leaks. UDP can't go around the proxy.
  • Finds your proxy. v2rayN, Clash, NekoRay, sing-box, Hiddify... and tries each one.
  • Checks your IP. See the address, place and network the world sees.
💡 Prefer your proxy's HTTP address: some apps' own code (Claude's, for one) can't use SOCKS outside Chromium.
twinbar ip "Slack Work"
For terminal people

All of it from the command line too

The window and the commands share the same code. Script it, automate it, or just type.
